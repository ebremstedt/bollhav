## [3.0.0] - 2026-06-11

Major release — internals reworked; several breaking changes.

### Removed

- **Directives** — gone. Run mode (reload / latest / backfill) now resolves a `[since, until)` **window** carried on the returned `ModelRun` (`run.window`, with `run.is_reload` / `is_latest` / `is_backfill`).

### Changed

- **`@load_models` hands back `ModelRun`s, not `Model`s** — each is a matched model (overrides baked into `target` / `batching`) paired with its resolved `window`.
- **Batching cleaned up** — `batching.time` (`chunk` / `window` / `lookback` / `tz`) is the single source for chunking, overridable per run via the `*_OVERRIDE` env vars.
- **State, library & errors centralised** — moved from per-target `z_<target_schema>` into one shared `z_bollhav` schema (one `errors` table, one cross-pipeline `library` registry).
- **State tables named by canonical identity** — hashed from the base `catalog.schema.name`, not the suffix/week-resolved name, so a model keeps one stable state-table name across the `z_bollhav_<suffix>_<week>_` schema rotation.
- **Staging** — per-interval tables self-clean inside the flush transaction (`keep_after_apply` to retain); backend options live on `PostgresStaging` / `MssqlStaging`.

### Added

- **Model kinds** — `interval` / `monolithic` / `view` (`Kind`); monolithic & view track a single NULL-window state row instead of per-interval rows.
- **Typed upstream contracts** — `IntervalContract` / `ViewContract` / `MonolithicContract` gate a model on upstream satisfaction by kind.
- **Curfew** — wall-clock windows and/or weekdays gating when a model may run (`allowed=` flips deny ↔ allow).
- **Schema-suffix environments** — `SCHEMA_SUFFIX` isolates state + data into suffixed schemas; `clear_state` / `drop_environment` tear an ephemeral env down.
